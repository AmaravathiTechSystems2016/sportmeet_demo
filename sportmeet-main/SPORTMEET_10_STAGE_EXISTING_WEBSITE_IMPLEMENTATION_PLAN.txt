A complete sports venue and event booking marketplace where:
- Public users can discover venues, sports, and events.

5. KNOWN ISSUES AND PENDING INTEGRATION
======================================================================

Database:
- Local development now uses SQLite.
- Original project was PostgreSQL-oriented.
- masterdata.sql is a PostgreSQL dump and cannot be imported directly into SQLite.
- PostgreSQL is recommended for production continuation.
- MySQL can be added later if required, but migrations, JSON fields, date behavior, and search/filter logic must be retested carefully.

Images and media:
- Local media now works because DJANGO_DEBUG=True is set.
- Production needs proper static/media hosting.
- Sports categories should eventually use unique realistic sport images instead of one repeated fallback.

Single pages:
- Venue and event detail routes have been verified locally.
- Event detail was fixed to use cover_image_url.
- More end-to-end browser testing is still needed after UI changes.

Frontend warnings:
- Build succeeds, but there are many lint warnings.
- Warnings include unused imports/variables, hook dependency warnings, alt text warnings, and one mixed-operator warning in BookingDetailPage.

Admin stats:
- Some admin stats use old wording such as active venues.
- Venue.status uses approved/pending/rejected/suspended.
- The dashboard should show approved venues instead of active venues, or clearly map active to approved.

Venue pricing:
- Venue base_price_per_hour is stale.
- Pricing should come from Court.price_per_duration and/or VenuePricing.
- Venue listing filters and sorting should use aggregated court pricing.

Payments:
- Stripe code exists but needs test/live keys.
- PaymentIntent, payment confirmation, webhooks, failed payments, refunds, and receipts need full testing.

Social login:
- Facebook and Google endpoints/pages exist.
- Valid OAuth app IDs/secrets and redirect URLs are required.

Maps/location:
- Mapbox dependency exists.
- REACT_APP_MAPBOX_TOKEN is not configured.
- All map UI must degrade gracefully without a token.
- Production nearby search should use PostgreSQL/PostGIS if location becomes a core feature.

Email/notifications:
- SMTP placeholders exist.
- Booking confirmations, password reset, owner notifications, event reminders, and admin alerts need implementation.

Redis/Celery:
- Packages exist.
- Redis server and Celery worker/beat are not fully wired for local operation.
- Background jobs should be completed for reminders, email queues, reports, and expiry tasks.

Invoices:
- apps/invoices exists or is referenced, but is not fully integrated into INSTALLED_APPS/main URLs.
- Invoice/receipt work should be treated as pending.

Reports:
- Report endpoints exist but numbers need validation against business requirements.

Authorization:
- Permissions must be audited endpoint by endpoint.
- Players should only access own data.
- Venue owners should only access own venues/bookings.
- Admin endpoints should be admin-only.
