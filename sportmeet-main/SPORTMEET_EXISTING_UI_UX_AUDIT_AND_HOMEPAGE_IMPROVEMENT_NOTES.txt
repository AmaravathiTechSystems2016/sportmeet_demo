Purpose
This document explains the current UI/UX of the SportMeet application only.
It is intended to help decide what should be improved visually, structurally, and experientially before more feature work is planned.

This document focuses on:
- Frontpage / homepage.
- Public navigation.
- Venue discovery and venue booking UI.
- Events and sports pages.
- Login/register/profile pages.
- Player dashboard and bookings.
- Venue owner dashboard, venues, and bookings pages.
- Admin dashboard and admin layout.
- Current strengths.
- Current UI/UX gaps.
- Detailed homepage improvement ideas.

This document does not focus on backend code, database logic, or production infrastructure except where those items affect visible UI/UX.

======================================================================
1. CURRENT DESIGN DIRECTION
======================================================================

Brand / visual identity:
- The current visible brand is SportMeet.
- The product message is "Discover, Book & Play."
- The latest theme direction uses green as the main brand color.
- Primary brand color now centers around #2eaf57.
- Most key public surfaces now use green for primary buttons, active states, and important accents.

Overall product feeling:
- SportMeet currently feels like a sports marketplace for:
  - finding venues,
  - booking courts,
  - joining events,
  - managing player activity,
  - managing venue owner operations,
  - running admin controls.

Visual style:
- Clean card-based layout.
- Light gray page backgrounds.
- White content cards.
- Green primary actions.
- Rounded-md controls and cards.
- Lucide icons are used widely.
- Layouts are generally practical and operational rather than decorative.

Current UI maturity:
- Public pages are present and mostly data-rich.
- Dashboard pages exist for player, venue owner, and admin.
- Empty states exist in many areas.
- Some older screens still use blue/purple styling.
- Some screens are more polished than others.
- Some buttons are visible but not always fully functional, especially in profile and some dashboard secondary actions.

2. GLOBAL NAVIGATION AND LAYOUT
======================================================================

Public header:
- Sticky top header.
- Left side shows logo or "SM" fallback and SportMeet name.
- Desktop nav includes:
  - Home
  - Venues
  - Events
  - Sports
  - List Your Venue
- Logged-out desktop actions:
  - Login
  - Sign Up
- Logged-in users see an account dropdown.
- Account dropdown includes:
  - Admin, if admin user.
  - Dashboard.
  - My Venues, if venue owner.
  - Bookings.
  - Profile.
  - Logout.

Mobile navigation:
- Hamburger menu opens stacked navigation.
- Links are large enough to tap.
- Auth links are separated in a bottom mini grid.
- Overall mobile header is understandable and not overcrowded.

Floating menu:
- Appears after scroll.
- Shows compact logo, search input on desktop, public links, venue owner CTA, login/dashboard controls.
- Useful for long homepage scrolling.
- Could be refined further because it duplicates some header behavior, but it is currently manageable.

Footer:
- Footer exists through layout.
- Contains brand identity and important quick links.
- Needs richer support/policy/content hierarchy if preparing for production.

Current global UI strengths:
- Navigation is role-aware.
- Public and admin areas are visually separated.
- Primary user paths are reachable from the header.
- The green brand color is becoming consistent.

Current global UI gaps:
- Some internal/admin/owner pages still use older blue/purple status colors.
- Several admin sidebar active states still use blue.
- Footer content could be more structured.
- No global breadcrumb system.
- No global "recently viewed" display yet, although recent venue tracking exists locally.
- No universal page intro pattern for all dashboards.

Recommended global improvements:
- Finish replacing remaining blue/purple primary states with #2eaf57 where they represent brand actions.
- Keep status colors semantic:
  - green for confirmed/approved/success,
  - yellow for pending/warning,
  - red for rejected/cancelled/error,
  - gray for inactive/neutral,
  - blue only for informational states if needed.
- Add breadcrumbs to detail and admin edit pages.
- Add consistent page headers with title, subtitle, and primary action.
- Add consistent empty state component across all pages.
- Add consistent table/list/card action patterns.
